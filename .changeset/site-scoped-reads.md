Each site's API and sitemaps answer for that site only. One deployment serves every website, and the REST API read with the same public access on every domain: `GET /api/pages` on one site returned the pages of all of them, and `/api/websites` listed every website with its domains. Public reads of the content collections (pages, articles, notes, products, cases, happenings, instructions, quotes, sources, terms, timelines, topics) and of the websites are now constrained to the website whose `domains` include the request's host, the same lookup the frontend makes. A host no website is configured for gets a 403. Users signed in to the admin are unaffected: the multi-tenant plugin keeps scoping members to their websites, and system admins see everything. The Local API called without a request stays unscoped, so server code that reads for a visitor still filters by tenant itself.

The sitemaps are built per site, for the host they are requested on. They used `NEXT_PUBLIC_CMS_URL` as the base, which is one URL for every site and in production was unset, so they listed `https://example.com/…`, and they listed every site's documents. The collection sitemaps now point at `/{locale}/c/{collection}/{slug}--{id}`, where those pages actually are (the `/c/` was missing), and use each locale's own slug. The pages sitemap lists the home page at the locale root and nested pages at their breadcrumb path, and no longer lists `/search`, which does not exist. Shared collections without a tenant (people, organizations) are listed on every site, as they are served on every site. The sitemaps are cached per site and rebuilt hourly, where before a collection sitemap was kept until the next restart.
